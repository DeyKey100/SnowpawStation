# Музыка и звуки Snowpaw Station

## Что подключено

- [AudioManager.cs](<../Assets/Game/Scripts/Audio/AudioManager.cs>) создаётся при запуске, живёт между сценами и использует два источника для плавных переходов музыки. SFX воспроизводятся из ограниченного переиспользуемого пула (по умолчанию 24 голоса).
- [PauseMenu.cs](<../Assets/Game/Scripts/UI/PauseMenu.cs>) напрямую управляет новым менеджером: включение музыки, отдельные ползунки «Громкость музыки» / «Громкость звуков», предыдущий / следующий трек, звуки кнопок и предпрослушивание громкости SFX. Метель сохранена.
- [ProximityInteractable.cs](<../Assets/Game/Scripts/Interaction/ProximityInteractable.cs>) автоматически добавляет [SfxEmitter.cs](<../Assets/Game/Scripts/Audio/SfxEmitter.cs>) **в рантайме**. Для дров/печи, снега, чашки и обычных предметов выбраны разные существующие звуки. Событие срабатывает при принятом нажатии взаимодействия, до вызова действия предмета; звук не означает гарантированный успех игрового действия.
- Радио и шаги/приземление ThirdPersonController учитывают общий ползунок звуков. Сюжетный радиоэфир временно подавляет фоновую музыку и освобождает подавление при остановке или завершении.

Объекты и аудиоисточники, добавленные при запуске, не сохраняются в файлы сцен. Существующие сцены, префабы и метафайлы не переписывались.

## Плейлист

По умолчанию используется папка `Assets/Game/Audio/Music` со всеми её подпапками. Поддерживаемые форматы: OGG, WAV, MP3, AIFF. Полные и `_lite` версии считаются отдельными треками. Случайный порядок перебирает плейлист, избегая немедленного повторения одного трека; плейлист из одного клипа зацикливается.

Чтобы настроить менеджер через Inspector, добавьте **Audio Manager** на отдельный корневой объект сцены. Он будет использован вместо автоматически создаваемого. Основные параметры:

- **Playlist Folder** — полная папка внутри `Assets/Game/Audio/Music` или относительная `Music/имя_подпапки`.
- **Playlist Clips** — необязательный список явных ссылок, имеет приоритет над папкой.
- **Shuffle Playlist**, **Play On Start**, **Fade Seconds** — порядок, автозапуск и плавность переходов.
- **Music Gain** — запас по уровню музыки. По умолчанию `0.3`, как у старого плеера: 100% на ползунке не равны полной громкости AudioSource.
- **Sfx Pool Size** — максимальное число голосов. При переполнении переиспользуется старейший; новые объекты на каждый звук не создаются.
- **Music Output / Sfx Output** — необязательные AudioMixerGroup. Создавать AudioMixer для работы ползунков не требуется.

Пользовательское отключение музыки не равнозначно сюжетному подавлению. Изменение громкости не переключает состояние «Вкл/Выкл».

## SFX на предмете или кнопке

Добавьте **SFX Emitter** на тот же объект, что и интерактивный маркер или uGUI Button:

1. Назначьте **Clip**, массив **Variations** или **Fallback Sfx Path** (например `WAV/Fireside/log_drop_01.wav`). Пустые элементы массива игнорируются. Явные настройки имеют приоритет над автоматически выбранным звуком.
2. Настройте громкость, 2D/3D, дистанцию, высоту тона и cooldown. Кнопка автоматически звучит в 2D и остаётся слышимой в меню паузы.
3. Автоматические **Play On Interact** / **Play On Button Click** уже подключаются и отключаются вместе с компонентом. Не назначайте тот же `Play()` дополнительно на тот же onClick, если не нужен повторный вызов.

Для других систем доступны `Play()`, `Stop()` и `OnInteract()` в UnityEvent. По умолчанию уже начатый звук переживает отключение/удаление предмета; **Stop On Disable** меняет это поведение. Отложенный запрос до готовности аудиобиблиотеки отменяется при отключении.

## Музыка по триггеру / событию

[MusicTrigger.cs](<../Assets/Game/Scripts/Audio/MusicTrigger.cs>) работает с Collider, у которого включён **Is Trigger**. Добавляйте компонент после коллайдера при создании объекта кодом. Для физического события нужна подходящая пара коллайдеров / Rigidbody или CharacterController; рекомендуемый простой вариант — один BoxCollider-триггер зоны и существующий игрок.

По умолчанию компонент ищет тег `Player` на вошедшем коллайдере или его родителях:

- Первый вход — музыка плавно затихает и ставится на паузу.
- Последний выход — музыка возвращается с сохранённой позиции.
- Перекрывающиеся зоны не отменяют блокировку друг друга.
- Отключение зоны освобождает её блокировку; уничтоженные/отключённые коллайдеры очищаются в FixedUpdate.

В UnityEvent доступны `SuppressMusic()`, `ReleaseMusic()`, `SetMusicSuppressed(bool)` и команды воспроизведения/выбора плейлиста. `ReleaseMusic()` снимает только событийную блокировку этого компонента: нахождение внутри активной зоны продолжает подавлять музыку.

Пример из другого компонента:

```csharp
// Начало сюжетного события — this должен быть живым UnityEngine.Object.
AudioManager.EnsureInstance().SuppressMusic(this, true);

// Конец события (также освобождайте свою блокировку в OnDisable).
AudioManager.Instance?.SuppressMusic(this, false);

// Выбор трека и одноразовый звук.
AudioManager.EnsureInstance().PlayTrack(0);
AudioManager.Instance.PlaySfx(clip, transform.position, volume: 0.8f);
```

`PauseMusic()` — временная пауза, `PlayMusic()` — запрос продолжения, `StopMusic()` — плавная остановка с освобождением текущего клипа. Они не меняют пользовательскую настройку и не снимают чужие блокировки.

## Настройки uGUI и сохранение

В текущем меню используются IMGUI-ползунки: ничего дополнительно назначать не нужно. Для будущего Canvas есть [AudioSettingsBinder.cs](<../Assets/Game/Scripts/Audio/AudioSettingsBinder.cs>): отдельные ссылки на Music/SFX Slider и необязательный Toggle. Диапазон 0–1 или 0–100 нормализуется автоматически; **Whole Numbers** лучше выключить. Обратная синхронизация использует WithoutNotify и не создаёт цикл событий.

Сохранённые ключи музыки сохранены: `snowpaw.music.enabled` и `snowpaw.music.volume`. Добавлен `snowpaw.sfx.volume`. Сохранение на диск отложено на 0.4 секунды после последнего изменения и принудительно выполняется при закрытии меню/паузы, отключении менеджера и выходе из приложения.

В меню паузы мировые звуки приостанавливаются через AudioListener.pause, музыка и 2D-звуки интерфейса продолжаются. При выходе восстанавливается предыдущее состояние слушателя.

## Сборка

[AudioLibrary.cs](<../Assets/Game/Scripts/Audio/AudioLibrary.cs>) читает каталог через AssetDatabase только в Editor. В standalone-сборках [AudioBuildProcessor.cs](<../Assets/Game/Editor/AudioBuildProcessor.cs>) автоматически копирует оригинальные аудиофайлы и каталог в **выходную папку собранной игры**, в `StreamingAssets/SnowpawAudio` внутри папки данных игрока. Исходные ассеты, GUID и папки проекта не перемещаются.

Автоупаковка поддерживает Windows, Linux и macOS standalone. Для Android/iOS/WebGL используйте явный **Playlist Clips** и назначенные SFX Clip либо отдельно подготовьте совместимый каталог StreamingAssets; автоупаковка для этих платформ не реализована. Обычные выбранные музыкальные клипы загружаются по мере надобности (соседние треки во время перехода), короткие SFX кешируются при запуске. Библиотеку можно проверить через `AudioManager.IsReady` / событие `Ready`.

## Совместимость и ручная проверка

[MusicPlayer.cs](<../Assets/Game/Scripts/Core/MusicPlayer.cs>) теперь только адаптер, не создаёт собственного источника. Он оставлен из-за существующих ссылок из сцены и меню; имена и типы его сериализованных полей сохранены. **BREAKING при будущем удалении:** сначала необходимо мигрировать компонент и все ссылки штатными средствами Unity, иначе появится Missing Script. В этой реализации переименований сериализованных полей нет.

После импорта исходников в Unity:

1. Play → Esc → Настройки: проверить независимость обоих ползунков, переключение треков, SFX кнопок, переход между сценами и восстановление значений после повторного запуска.
2. Проверить вход/выход двух перекрывающихся музыкальных зон, отключение зоны внутри неё, взаимодействие с исчезающим предметом, сюжетное радио и standalone-сборку. Прослушивание и визуальный вид интерфейса не проверялись инструментом скриншотов.
